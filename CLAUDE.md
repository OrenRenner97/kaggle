# Kaggle++

Соревнования Kaggle как имитация реального ML-проекта. Общаемся на русском.

## Процесс

1. Новое соревнование → Claude пишет `BRIEF.md` по шаблону: выдуманная (но правдоподобная) компания, боль, заказчик,
   команда и роли, ограничения. Сценарии каждый раз разные: отрасль, команда, ограничения, паттерн деплоя.
   Не примитив и не переусложнение.
2. Этапы 1–10 из README идут **по одному, с остановкой и обсуждением после каждого**.
3. На каждом этапе разбираем четыре стороны: матчасть, ML, Python, аналитика/бизнес — и пишем это в журнал.
4. 1–2 «вводные» от заказчика за соревнование (смена требований, сломанные данные, новый источник) — в подходящий момент.

## Кто что пишет (по умолчанию, можно менять в BRIEF)

- Claude играет заказчика, тимлида-ревьюера, DE и MLOps; пользователь — DS/ML. Роли можно менять на этапе.
- Исследование и модели (этапы 1, 4, 6, 7): пользователь пишет первым, Claude ревьюит, объясняет матчасть, дополняет.
- Инфраструктура (этапы 2, 3, 5, 8, 9): пишем вместе; Claude может делать каркас, пользователь — ключевые части.
- Перед правкой кода пользователя — сверяемся с ним; его исходный вариант не затираем, замечания пишем в журнал.

## Структура соревнования `competitions/NN_slug/`

`BRIEF.md`, `README.md` (журнал этапов по шаблону), дальше папки по мере этапов:
`sources/` (генерация сырых систем), `pipelines/` (ETL), `research/` (ноутбуки), `features/`, `models/`,
`deploy/`, `monitoring/`, `submissions/` (в .gitignore). Тесты рядом: `test_*.py`.

## Документация обязательна

- Журнал этапа в `competitions/NN_slug/README.md` + строка в `competitions/README.md` и `PROGRESS.md`.
- Новое в `src/mlkit/` → строка в `src/mlkit/README.md` + тест в `tests/`.
- Новый сервис → профиль в `infra/docker-compose.yml` + строка в `infra/README.md`.

## Ограничения

- Данные, артефакты моделей, токены — никогда в git (см. `.gitignore`). Kaggle-токен: `~/.kaggle/access_token`.
- Железо: RTX 3050 6 GB, 30 GB RAM (обычно ~22 занято), 12 ядер. Тяжёлые сервисы — профилями, поднимать на этап и гасить.
  Большие данные — polars/DuckDB, не pandas целиком в память.

## Команды

- `uv sync --all-extras`, `uv run pytest`, `make download C=<slug>`, `make submit C= F= M=`, `make infra-up`, `make mlflow`.
